# 00 · 总览

> 一句话：**让普通用户能「装一次、点几下、之后不用管」地使用 IMAP 中继。**

---

## 1. 为什么需要一个 GUI

中继本体（peon-burrow 仓库）是一个命令行程序 + 系统服务。它对普通用户有三个门槛：

| 门槛 | 现实 |
| --- | --- |
| 不知道去哪下载 | 用户不会去 GitHub Releases 找 `peon-burrow-x86_64-pc-windows-msvc.zip` |
| 不知道怎么装成服务 | `service install --mode user --autostart logon` 不是普通人能敲的 |
| 不知道服务到底有没有在跑 | 没有界面 = 只能去任务管理器猜，或者干脆以为坏了 |

本应用就解决这三件事：**给下载、给按钮、给状态**。

---

## 2. 目标（可验收）

| # | 目标 | 验收 |
| --- | --- | --- |
| G1 | 显示**服务安装状态**与**运行状态**（四种组合都能区分） | 手动造出四种状态，界面文案与按钮都对 |
| G2 | 五个操作可用：安装服务 / 卸载服务 / 启动 / 停止 / 开机自启开关 | 每个操作后状态在 3 秒内刷新正确 |
| G3 | **主路径零 UAC**（用户级自启） | 干净机器上安装全过程不弹 UAC |
| G4 | 需要提权时**说清楚**、被拒绝时不报「错误」 | 取消 UAC 后界面显示「已取消」，状态不变 |
| G5 | 显示「扩展里该填的地址」并能一键复制 | 点一下就复制到剪贴板 |
| G6 | 诊断视图能显示 core 的 `doctor` 结果 | 端口被占等场景显示 PID + 建议动作 |
| G7 | **不做自更新** | 代码里没有任何 updater 相关依赖或配置 |

---

## 3. 非目标

| 非目标 | 理由 |
| --- | --- |
| 内嵌中继逻辑 | 中继由服务常驻运行。GUI 关掉不影响收信 |
| 自己实现服务注册 | 逻辑两份必然漂移（[adr-0006 § Q2](../../peon-burrow/ai-docs/decisions/adr-0006-desktop-installer.md)） |
| 自更新 | 需求明确不要；免安装工具重装即可 |
| 账号/凭据管理 | **中继不落盘任何凭据**，GUI 更不该碰（core 的控制面命令白名单里也没有这类命令） |
| 修改中继监听端口 | 改端口需要重启 + 同步改扩展里的地址；放配置文件里更不容易误触。GUI 只显示 + 「打开配置文件」 |
| 托盘常驻 / 开机自启 GUI 自己 | 首版不做。GUI 是偶尔打开的安装器，不是常驻应用 |

## 4. 与用户的交互全貌

```
用户下载安装包（.msi / .dmg / .AppImage）
   └─ 打开「peon-hall」
        ├─ 首次打开：状态卡片显示「未安装」
        │    └─ 点【安装服务】
        │         ├─ 默认：用户级自启（零 UAC）→ 安装并启动 → 卡片变「正在运行」
        │         └─ 高级选项：系统服务（提权一次）
        ├─ 日常：打开就是状态 + 【停止】【重启】【卸载服务】【开机自启 ✔】
        ├─ 出问题：点【诊断】→ 显示 doctor 结果（端口被占、服务没起、自启没配）
        └─ 收不到邮件：【复制扩展地址】→ 粘到扩展的账号配置里
```

## 5. 组件

```
desktop/
├── package.json                  # 版本唯一来源（见 04-release.md § 1）
├── vite.config.ts
├── src/                          # 前端
│   ├── main.ts
│   ├── App.vue
│   ├── components/
│   │   ├── StatusCard.vue        # 状态卡片（四组合）
│   │   ├── ActionBar.vue         # 5 个操作
│   │   ├── AutostartSwitch.vue   # 开机自启开关（含「系统服务」标记）
│   │   ├── DoctorPanel.vue       # 诊断结果列表
│   │   └── RelayAddress.vue      # 扩展地址 + 复制按钮
│   └── ipc.ts                    # 调 Tauri 命令的薄封装（类型来自 Rust 侧）
├── src-tauri/
│   ├── Cargo.toml                # peon-burrow-ipc 通过 git 依赖钉 tag
│   ├── tauri.conf.json           # externalBin(sidecar)、bundle targets、identifier
│   ├── capabilities/default.json # shell:allow-execute（sidecar）、clipboard 等
│   ├── binaries/                 # 打包时放进来的 core 二进制（.gitignore）
│   └── src/
│       ├── main.rs
│       ├── control.rs            # 控制面客户端（读状态、发命令）
│       ├── sidecar.rs            # 调 core 的 service 子命令（含提权分支）
│       └── commands.rs           # 暴露给前端的 Tauri 命令
└── ai-docs/
```

**职责边界**：前端只负责**渲染与交互**；所有系统动作（读服务状态、调 sidecar、提权）
都在 Rust 侧。前端的 `ipc.ts` 里不出现任何平台判断。

## 6. 成功判据（D6 结束时）

在一台**干净的 Windows 机器**（没有 Node、没有 Rust、没有中继）上：

1. 双击 `peon-hall_0.1.0_x64-setup.exe` → 装完自动打开；
2. 界面显示「未安装」→ 点【安装服务】→ **没有 UAC** → 3 秒内变成「正在运行 · 端口 41316 · v0.1.0」；
3. 点【复制扩展地址】→ 粘到扩展的账号页 → 能收到验证码邮件；
4. **重启机器** → 打开 GUI → 显示「正在运行」（不需要任何操作）；
5. 点【停止】→ 扩展变成「重连中」；点【启动】→ 恢复；
6. 点【诊断】→ 正常情况全绿；
7. 点【卸载服务】→ 状态回到「未安装」，扩展失联，配置与日志按选择保留。
