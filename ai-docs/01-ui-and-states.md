# 01 · 界面规格与状态

> 界面的**唯一目的**是让用户知道「现在是什么状态」和「我该点哪个按钮」。
> 所有文案遵循 peon-burrow 仓库的规范：
> `ai-docs/design/logging-and-diagnostics.md § 4`（说人话、给下一步、不甩锅、可复制）。

---

## 1. 窗口

| 项 | 值 | 理由 |
| --- | --- | --- |
| 标题 | `peon-hall` | 面向用户的名字；「relay / 中继」是内部术语，只在诊断视图里出现 |
| 初始尺寸 | 560 × 460 | 刚好放下状态卡片 + 5 个按钮 + 一行地址 |
| 最小尺寸 | 520 × 420 | 防挤压布局 |
| 可调整大小 | 是 | 诊断结果可能很长 |
| 菜单栏 | 无 | 只有一个页面 |
| 托盘图标 | **暂不做** | GUI 是「偶尔打开」的安装器，不是常驻应用；开机自启的是**服务**不是 GUI |
| 深色模式 | 跟随系统 | 前端用 CSS `prefers-color-scheme` |

---

## 2. 状态：两个来源，四种组合（核心）

**这是本应用最主要的价值** —— TS 版时代用户完全无法区分这些状态。

```
         ┌── 服务管理器（是否注册 / 是否自启）  ← 权威①
状态卡 ──┤    Windows：任务计划程序 或 SCM
         │    macOS：launchd   Linux：systemd / XDG autostart
         └── 控制面（进程内真实状态）           ← 权威②
              peon-burrow-ipc：ping / status / version
```

| 已注册 | 控制面可连 | 卡片文案 | 副标题 | 主按钮 | 次按钮 |
| --- | --- | --- | --- | --- | --- |
| ✅ | ✅ | **正在运行** | `端口 41316 · 中继 v0.1.0 · 1 个监听` | 停止 | 重启 |
| ✅ | ❌ | **已安装，未运行** | `上次退出码 4（更新后重启中）` 或 `服务未启动` | 启动 | 卸载服务 |
| ❌ | ✅ | **前台运行中** | `未安装为服务（重启机器后不会自动运行）` | 安装服务 | 停止 |
| ❌ | ❌ | **未安装** | `安装后即可在扩展里收邮件` | 安装服务 | — |

附加信息行（任何时候都显示，值来自发现文件 / 控制面）：

| 字段 | 来源 | 显示 |
| --- | --- | --- |
| 开机自启 | 服务管理器 | `开机自启：登录时启动` / `开机自启：已关闭` / `—`（未安装） |
| 安装级别 | 服务管理器 | `用户级（不需要管理员）` / `系统服务` / `—` |
| 扩展地址 | 发现文件（或默认值） | `ws://127.0.0.1:41316/` + 【复制】 |
| 版本 | 控制面 `version` | `v0.1.0 (a1b2c3d)`，悬停显示构建时间 |

⚠️ **区分「未安装」与「已安装未运行」的判据只能是服务管理器**，
不能靠「端口连不上」推断 —— 前台运行（未安装）时端口是通的。

## 3. 五个操作（需求清单）

| 操作 | 何时可用 | 是否需要提权 | 做了什么 |
| --- | --- | --- | --- |
| **安装服务** | 未注册时 | 用户级：否 / 系统服务：是 | 提权必要时 spawn `burrow service install --mode <user\|system> --autostart logon` |
| **卸载服务** | 已注册时 | 同上（按当前安装级别） | `service uninstall`（先停服务） |
| **启动** | 已注册但未运行 | 用户级：否 / 系统服务：是 | `service start` |
| **停止** | 运行中 | **否**（走控制面让服务自己停） | 控制面 `stop`；系统服务模式下若控制面不可连，则降级为提权 `service stop` |
| **开机自启开关** | 已注册时 | 同安装级别 | `service autostart on\|off` |

三个低成本高收益的附加项（不是需求，但强烈建议）：

| 附加项 | 说明 |
| --- | --- |
| **复制扩展地址** | 过渡期（扩展默认端口还没改）用户最容易错的一步 |
| **诊断** | 调控制面 `doctor`，把 13 项检查渲染成可折叠列表；失败项带「执行建议动作」按钮 |
| **打开配置 / 日志目录** | 用系统文件管理器打开；配置目录里放一个 `README.txt` 说明可改哪些字段 |

### 3.1 操作的通用交互

```
点按钮
 ├─ 立即使按钮进入「进行中」（禁用 + 转圈 + 文案「正在安装…」）
 ├─ 调 Rust 命令（await）
 ├─ 无论成功失败，都重新拉一遍状态（**失败也要拉** —— 失败往往改变了状态）
 └─ 结束「进行中」，显示结果
```

| 情况 | 显示 |
| --- | --- |
| 成功 | 卡片刷新；不弹对话框（状态本身就是反馈） |
| 需要提权被取消（UAC / polkit 拒绝） | 顶部一条黄色提示：`已取消（安装系统服务需要管理员权限）`。**不叫「错误」** |
| 失败 | 红色提示 + 一行「人话」原因 + 【诊断】按钮（不要只丢原生错误码） |
| 超时（> 30 秒） | `操作超时，服务可能仍在启动中` + 【刷新状态】 |

⚠️ 提权操作**不要**在成功路径上弹「成功」对话框：用户点「安装服务」，
期待的是卡片变成「正在运行」，不是再点一次「确定」。

## 4. 自动刷新

| 触发 | 行为 |
| --- | --- |
| 打开窗口 / 窗口获得焦点 | 立即刷新 |
| 每 2 秒（仅窗口可见时） | 轮询控制面 `ping`（轻）+ 每 5 次轮询查一次服务管理器状态 |
| 任何操作结束后 | 立即刷新 |
| `ping` 连续失败 3 次 | 卡片切到「未运行/不可连」的组合，**并把轮询退避到 10 秒**（避免打日志刷屏） |

> ⚠️ 不要为了省事每秒都去查服务管理器（`schtasks` / `launchctl` / `systemctl`
> 都是**进程调用**，成本远高于一次本地 socket ping）。

## 5. 异常与边界状态

| 场景 | 界面 |
| --- | --- |
| sidecar 二进制缺失（安装包损坏） | 卡片显示 `安装不完整：缺少中继程序`，所有操作禁用，给【重新安装】提示 |
| 平台不支持（如 32 位 macOS） | 应用根本不会构建出来；若运行时报错则显示「当前系统不受支持」 |
| 控制面连不上但服务管理器说运行中 | 组合②「已安装，未运行」+ 一行 `（可能正在重启或更新中）` |
| 端口被别的进程占用 | 卡片显示「未运行」+ 诊断里显示 PID/进程名/三条出路 |
| 用户手动删了安装目录的 exe | 卡片「已安装，未运行」+ 诊断提示「安装目录里的程序不见了，请卸载后重装」 |
| 读取状态本身失败 | 显示原始原因 + 【复制诊断信息】（方便用户贴工单） |

## 6. 诊断视图

调控制面 `doctor`（结构化 JSON，见 peon-burrow 仓库
`ai-docs/design/logging-and-diagnostics.md § 3`），渲染成：

```
✅ 配置            %APPDATA%\peon-burrow\relay.toml
✅ TLS 根证书
⚠️ 端口 41316      被 chrome.exe（PID 8899）占用          【换端口】
✅ 服务            已安装（用户级 · 登录时启动）
✅ 控制面          可连
✅ 安全            loopback + token 已设置
✅ 自更新          24 小时前检查过，当前为最新
   扩展地址         ws://127.0.0.1:41316/                【复制】
```

- 每项一行，前缀 ✅ / ⚠️ / ❌；
- 有「建议动作」的项显示一个按钮（`换端口` = 打开配置文件；`启动服务` = 调 `service start`）；
- 底部【复制全部】把纯文本结果放进剪贴板（用户贴 issue 用）；
- ⚠️ **凭据永远不出现在诊断结果里**（peon-burrow 侧已保证：只显示「已设置 / 未设置」）。

## 7. 文案规范（沿用 core 的规则）

| 场景 | ❌ | ✅ |
| --- | --- | --- |
| 端口被占 | `bind failed: EADDRINUSE` | `端口 41316 被 chrome.exe 占用了。要么改配置里的端口，要么先关掉它。` |
| 未安装但用户点了停止 | 灰按钮无说明 | 按钮禁用 + 悬停提示「服务还没安装」 |
| 提权取消 | `操作失败` | `已取消（安装系统服务需要管理员权限）` |
| 服务未运行 | `connection refused` | `服务没有在运行。点【启动】。` |

原则（与 core 一致）：**说人话 / 给下一步 / 不甩锅 / 可复制**。

## 8. 验收

| # | 断言 |
| --- | --- |
| 1 | 四种状态组合都能被造出来并正确渲染（手动构造：装/不装 × 跑/不跑） |
| 2 | 五个操作在「不该可用」时都禁用且给出原因 |
| 3 | 用户级安装全程无 UAC；系统服务安装恰好弹一次 |
| 4 | 取消 UAC → 显示「已取消」，状态不变，不产生「错误」记录 |
| 5 | 操作完成后 3 秒内状态刷新正确（含失败的情况） |
| 6 | 控制面断开时轮询退避，不会每秒刷错误 |
| 7 | 【复制扩展地址】写进剪贴板的内容与发现文件里的 `url` 完全一致 |
| 8 | 诊断视图的每一项与 core 的 `doctor` 输出一一对应，且**不含任何凭据** |
| 9 | 设备像素比 1 / 2、深色 / 浅色下布局都不破 |
| 10 | 窗口缩放与最小尺寸下按钮不被裁切 |
| 11 | 没有 updater 相关依赖（`Cargo.toml` / `tauri.conf.json` 里搜不到 updater） |
| 12 | 中继未安装时，界面不显示任何「中继 vX」版本号（避免误导） |
